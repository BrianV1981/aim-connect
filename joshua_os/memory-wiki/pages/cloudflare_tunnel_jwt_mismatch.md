# Cloudflare Tunnel Crash & JWT Signature Mismatch

## Context
During operations involving the Next.js Vercel frontend (`leaddeed-dashboard`) connecting to the FastAPI backend via `wss://api.leaddeeds.com/ws`, the UI continuously reported:
`Connection closed by remote node. Connecting to secure node...`

This error masked two distinct, overlapping architectural failures.

## 1. The JWT Signature Mismatch
The primary backend expects a JWT generated by the frontend, signed with `LEADDEED_DOWNLOAD_SIGNING_SECRET`.
- When the frontend and backend `.env` variables become out of sync, the `_verify_dashboard_jwt` function throws an HTTP 1008 `Invalid API Token` closure.
- The `AgentTerminal.tsx` UI interprets this clean disconnect as a generic `Connection closed by remote node.`.

## 2. The Cloudflared Argo Tunnel Crash (Masking)
The Vercel production frontend explicitly hardcodes the WebSocket path to `wss://api.leaddeeds.com/ws`.
- This domain relies on a running `cloudflared` tunnel (an Argo Tunnel) on the backend host to proxy traffic to the local `uvicorn` instance on port 8000.
- If the `cloudflared` process is killed (e.g., a blind `tmux kill-session` sweep or system reboot), Cloudflare returns an HTTP `530 Origin Error` (Argo Tunnel Error).
- The `AgentTerminal.tsx` UI intercepts the WebSocket network failure and displays the exact same `Connection closed by remote node.` error as a 1008 JWT rejection.

## Resolution Workflow
When encountering this opaque UI error, Operators must always verify the network layer *before* debugging the authentication layer:

1. **Verify the Cloudflare Tunnel:**
   Run a `curl -I https://api.leaddeeds.com` test.
   - If it returns `530`, the tunnel is down. You must relaunch `cloudflared` (e.g., `cloudflared tunnel run <tunnel_id>`).
   - If it returns `405 Method Not Allowed`, the tunnel is successfully routing to the Uvicorn FastAPI backend (which expects WebSocket traffic, not HTTP GET).

2. **Verify the JWT Secret:**
   Ensure the backend `.env` file explicitly defines the `LEADDEED_DOWNLOAD_SIGNING_SECRET` and matches the Vercel production `.env.local` secret string identically.
